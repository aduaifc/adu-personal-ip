## 8 项测试

1. 实际生成示例文件齐全、PNG 可解码且存在真实透明背景和可见前景。
2. 有 alpha 通道但完全不透明的图，不能当作透明人物图通过。
3. 完全不可见的透明空图，不能当作有人物的透明图通过。
4. 缺少已请求的三视图时检查失败。
5. 资产使用越出角色包的相对路径时检查失败。
6. 生成记录指向不存在的参考图片时检查失败。
7. 仍待用户确认的角色不能标记 ready。
8. 截断 PNG 被拒绝。

测试只在临时测试目录制造缺失文件／损坏图片，不修改真实示例和用户源文件。图像检查器验证 PNG 数据块长度、解压与像素结构，不是通用图像安全审计工具；不验证 CRC 或 C2PA 签名。

## 核对发现与处理

- 第一张预览补全了下方两侧斜插袋；它们与最初指定的单个左胸竖袋不冲突，已在后续角色约定和提示中明确。
- 透明图的最大 alpha 为 254，所以“alpha 小于 255 的像素数量”会把整张图都算进去。检查器增加完全透明背景和近不透明前景的统计，避免把微透明整图误认为合格抠图。
- 最终透明图 1024×1536；有 1,116,055 个 alpha=0 的像素、413,414 个近不透明像素，四角 alpha 均为 0。它不是只改扩展名的白底文件。
- 图像工具没有报告模型标识，生成记录如实写 `not-reported`，未补造版本。

## 未验证与局限

- 本次只有文字创建路线做了真实图片试跑；真人照片、其他外部角色和用户定点改稿路线没有实际生图验证。
- 没有在所有 AI 客户端安装试用；图像工具接口由客户端提供，纯文本客户端不会因此获得生图能力。
- 颜色、服装纹理和比例可能随生成发生细小变化；检查器无法自动确认人脸一致性和权利来源。
- 透明轮廓存在模型软边；最终用于深色／彩色背景时仍需在实际版面检查。三视图只是二维图片，不是 3D 模型。
- 用户把示例设计委托给助手，没有逐张确认阿禾为自己的品牌形象。示例不能代表用户的审美认可。
- 本文不承诺后续模型、额度或服务条款保持不变。

## 本地复查

有 Node.js 18+ 时，在仓库根目录执行：

```bash
node --check scripts/check-pack.mjs
node --test
node scripts/check-pack.mjs examples/ahe
```

使用 Skill 本身不需要安装 PyYAML；它只在此次开发中为运行宿主的结构检查器而临时使用，没有打包到仓库。
